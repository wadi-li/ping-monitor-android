# Пинг-монитор для Android

Нативное приложение для постоянного контроля доступности 1–50 выбранных адресов. Мониторинг выполняет Android foreground service, а не HTML-страница или WebView. Интернет нужен только для проверяемых сетевых адресов: CDN, аналитики, рекламы и обязательного облачного сервера нет.

## Возможности

- **Проверки:** HTTP/HTTPS, TCP-порт и ICMP echo через системный `ping`.
- **Порядок адресов:** кнопки «Выше» и «Ниже» у каждого адреса. Порядок сохраняется и используется в списке, пакетах опроса, уведомлении и CSV.
- **Отключение отдельных адресов:** «Не опрашивать» / «Опрашивать». Адрес остаётся в списке, его прежняя статистика сохраняется; отключённый адрес не участвует в общем статусе.
- **Работа в фоне:** постоянный сервис и уведомление с действием «Стоп». Закрытие окна не является командой остановки.
- **Индикаторы:** зелёный, жёлтый, красный в приложении и цветные кружки в раскрытом уведомлении. В верхней строке состояния Android используются монохромные круги с галочкой, восклицательным знаком или крестом, поскольку Android показывает статусные значки монохромно. ([Документация Android](https://developer.android.com/design/ui/mobile/guides/home-screen/notifications))
- **Статистика:** последнее измерение, среднее по последним 10 попыткам с ответом, минимум/максимум, доля ошибок, число ошибок подряд, время последней проверки.
- **Графики:** 50 последних точек для каждого адреса; ошибки показаны разрывами. Нажатие на график открывает увеличенный просмотр с экспортом PNG.
- **Файлы:** импорт TXT/CSV, экспорт CSV с `;`, UTF-8 BOM и экранированием кавычек. Файлы выбираются через системный диалог без разрешения на весь накопитель.
- **Оформление:** светлая тема по умолчанию и переключатель тёмной темы.

## Установка и первый запуск

1. Скачайте `ping-monitor-1.0.0.apk` из раздела Releases этого репозитория.
2. Разрешите установку из выбранного источника, если Android запросит это.
3. Откройте приложение. Разрешите уведомления: без них приложение намеренно не запускает мониторинг, чтобы индикатор не оказался невидимым.
4. Нажмите «Добавить», введите нужные адреса, по одному на строку. Начальный `https://google.com/` можно изменить нажатием на адрес или удалить в его диалоге.
5. Расположите адреса кнопками «Выше» / «Ниже». Ненужные сейчас адреса отключите кнопкой «Не опрашивать».
6. В «Настройках» задайте интервал, таймаут, порог задержки и число последовательных ошибок.
7. Для мониторинга с выключенным экраном откройте «Батарея: убрать ограничения» и исключите приложение из оптимизации. На некоторых телефонах отдельно требуется разрешить фоновую работу/автозапуск в настройках производителя. Обычный foreground service сам по себе не снимает ограничения Doze на сеть и wake lock. ([Документация Doze](https://developer.android.com/training/monitoring-device-state/doze-standby))
8. Нажмите «Запуск» и сверните приложение. Разверните уведомление, чтобы увидеть цветные кружки.

Приложение рассчитано на Android 8.0 и новее, `minSdk 26`, `targetSdk 35`. Наличие API в диапазоне версий не означает проверку на всех моделях телефонов.

## Форматы адресов

```text
example.com
https://example.com/health?mode=ready
http://192.168.1.1/
tcp://192.168.1.1:443
icmp://1.1.1.1
tcp://[2001:db8::1]:443
```

Без протокола используется HTTPS. Сохраняются явно заданные HTTP/HTTPS, порт, путь и query; `http://host/health` и `https://host/` являются разными проверками. Поддерживаются международные DNS-имена и IPv6 в квадратных скобках.

Логин/пароль в URL и `#fragment` не поддерживаются. Не помещайте секретные токены в URL: адреса отображаются в уведомлении, CSV и локальных настройках. HTTP без шифрования разрешён для устройств локальной сети; HTTPS-сертификаты и имена серверов проверяются штатно, обход проверки TLS отсутствует.

### HTTP/HTTPS

Измеряется время до заголовков HTTP-ответа, включая DNS, установление соединения и TLS при необходимости. Это не ICMP-пинг. Используется HEAD с переходом на GET при HTTP 405 или 501; для GET запрашивается `Range: bytes=0-0`, тело ответа намеренно не читается.

Следуются максимум пять перенаправлений. HTTPS → HTTP возвращает предупреждение без перехода на незашифрованный адрес. 2xx/3xx считаются успешным ответом, 401/403/429 показываются жёлтым как ограниченный доступ; остальные 4xx/5xx считаются ошибкой.

### TCP и ICMP

TCP проверяет возможность подключения к указанному порту, но не исправность приложения за ним. ICMP использует системную утилиту без root; фильтрация ICMP или запрет `ping` в прошивке не доказывают, что HTTP-сервис недоступен. При запрете ICMP самой системой показывается жёлтое предупреждение с рекомендацией использовать TCP/HTTPS.

## Правила статусов

| Состояние | Условие |
|---|---|
| Зелёный | Последняя проверка успешна, задержка ниже порога, доля ошибок в последних 20 попытках менее 20% |
| Жёлтый | Нет первой проверки, временная ошибка до красного порога, высокая задержка, не менее 20% ошибок в последних 20 попытках, HTTP 401/403/429, устаревшие результаты или отсутствие сети телефона |
| Красный | Число последовательных ошибок достигло заданного порога |
| Серый | Адрес отключён кнопкой «Не опрашивать» |

Общий статус берётся по худшему состоянию включённых адресов. При отсутствии включённых адресов уведомление показывает ожидание, а не зелёный статус. Отсутствие сети телефона не записывается как отдельный сбой каждого сервера; счётчики в этот момент не увеличиваются.

После восстановления красный сменяется жёлтым, если в окне последних 20 проверок ещё велика доля ошибок. В CSV «Ошибки, %» вычисляются за всю накопленную статистику; для текущего цвета используется скользящее окно, а не весь срок наблюдения.

## Фоновая работа и ограничения

- **Архитектура:** `specialUse` foreground service с явным описанием назначения и соответствующим разрешением. Android требует указывать тип foreground service для приложений с target 34+; `specialUse` предназначен для подходящих сценариев, не покрываемых другими типами. Публикация такого приложения в Google Play требует отдельного рассмотрения назначения; этот проект поставляется APK для установки напрямую. ([Типы foreground services](https://developer.android.com/develop/background-work/services/fgs/service-types))
- **Питание:** по умолчанию удерживается частичный wake lock с обновляемым двухчасовым пределом. Он освобождается при остановке; режим можно отключить, если непрерывная работа с выключенным экраном не нужна.
- **Надёжность:** сервис запрашивает `START_STICKY`, но это не обещание немедленного или обязательного восстановления. Force-stop, перезагрузка, отзыв разрешений, управление питанием прошивки и убийство процесса могут остановить мониторинг. После перезагрузки запуск выполняется вручную.
- **Нагрузка:** одновременно выполняется до 10 запросов; цикл не накладывается на следующий. Интервал задаёт паузу после завершения цикла, а не точный период между стартами. Например, 50 недоступных адресов с таймаутом 3 секунды требуют примерно 5 пакетов по 3 секунды плюс заданная пауза.
- **DNS:** общий дедлайн ожидания включает DNS. Системное разрешение имени в Java может не завершиться немедленно при отмене; фиксированный пул и ограниченная очередь не допускают неограниченного размножения потоков. При заполнении очереди отображается предупреждение о занятой сети/DNS.
- **Изменения во время работы:** перестановка или переключение адреса отменяет текущий пакет и применяет новую конфигурацию; уже завершённые проверки не откатываются. Проверки внутри пакета параллельны, поэтому порядок начала/завершения запросов внутри пакета не гарантируется.
- **Уведомление:** один агрегированный значок в статусной строке. В раскрытой карточке до восьми включённых адресов в заданном порядке, затем указание количества оставшихся; полный список доступен в приложении.
- **Приватность:** адреса и последние 100 измерений на адрес сохраняются в приватных настройках приложения. Резервное копирование и перенос этих данных отключены. Экспорт и запросы к выбранным узлам выполняются только по действиям пользователя/включённому мониторингу.

## Сборка

Требуются JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Внешних runtime-зависимостей нет.

```bash
export ANDROID_HOME=/path/to/android-sdk
bash tools/test-core.sh
./gradlew :app:assembleRelease :app:lintDebug
```

APK: `app/build/outputs/apk/release/app-release.apk`. Gradle Wrapper закреплён на 8.11.1; Android Gradle Plugin: 8.9.2.

### Подпись APK

Текущая личная sideload-сборка подписывается Android debug-ключом, но собрана как `release` и не включает `android:debuggable=true`. Это не ключ для публикации в Google Play. Ключ не находится в Git; его копия сохранена как Actions secret `ANDROID_SIGNING_KEYSTORE` этого приватного репозитория, чтобы последующие CI-сборки могли обновлять уже установленный APK.

Локальная сборка на другой машине с другим debug-ключом не обновит установленное приложение: нужен тот же ключ либо удаление приложения с потерей локальных данных. Не удаляйте Actions secret, если хотите сохранить возможность совместимых обновлений.

## Проверки

Локальные JVM-регрессионные тесты запускаются командой `bash tools/test-core.sh`. Они проверяют URL, CSV, политику цветов, ограничение истории, настоящий HTTP/TCP на временном локальном сервере, перенаправления, HEAD → GET, ошибки, таймауты и неблокирующую отмену запроса.

Инструментальный тест Android не требует стороннего тестового runtime:

```bash
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell pm grant ru.limar.pingmonitor android.permission.POST_NOTIFICATIONS
adb shell am instrument -w ru.limar.pingmonitor.test/ru.limar.pingmonitor.SmokeInstrumentation
```

Тест очищает данные только тестовой установки, создаёт локальный HTTP-сервер, проверяет перестановку, отключение/возобновление адреса, статусы, работу после сворачивания и сохранение настроек. Не запускайте его поверх своей рабочей установки с нужной статистикой.

Подробный разбор исходного HTML: [docs/AUDIT.md](docs/AUDIT.md). Фактически выполненные проверки и непроверенные сценарии: [docs/TESTING.md](docs/TESTING.md).
