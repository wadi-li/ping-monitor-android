# Разбор исходного HTML-монитора

Исходный код предоставлен в сообщении пользователя. Для задачи постоянного Android-мониторинга он заменён нативной реализацией, а не упакован без изменений в WebView.

## Ошибки исходника

- **Область видимости:** `startPing`, `stopPing`, `generateReport`, `saveChart`, `clearStats`, `toggleAnimation` объявлены внутри IIFE, но вызываются из HTML через inline `onclick`. Они не экспортированы в `window`, поэтому такие обработчики не находят функции. Это самостоятельная причина неработающих кнопок.
- **Неверное понятие ping:** длительность `fetch` до ответа не является ICMP RTT. В новой версии режимы HTTP, TCP и ICMP разделены и подписаны.
- **Скрытый HTTP-ответ:** `no-cors` возвращает opaque response; JavaScript не может прочитать содержимое и заголовки, поэтому такой режим не позволяет корректно контролировать HTTP-состояние сервиса. В нативной версии используется доступный HTTP-код ответа. ([MDN Request.mode](https://developer.mozilla.org/en-US/docs/Web/API/Request/mode))
- **Потеря протокола:** `normalizeUrl()` возвращает только `u.host`; затем `pingSite()` всегда добавляет `https://`. Явно заданный HTTP превращается в HTTPS.
- **Потеря ресурса:** путь и параметры URL выбрасываются. Проверка `/health` фактически превращается в проверку `/`.
- **HEAD без fallback:** узел, который запрещает HEAD, может оказаться ошибочно отмеченным как недоступный. В новой версии при 405/501 применяется GET без чтения тела.
- **Длительный цикл:** 50 последовательных запросов по 3 секунды дают до 150 секунд ожидания, не считая паузы. Новая версия использует пакеты до 10 запросов.
- **Гонка остановки и запуска:** остановка не прерывает активный `fetch`, а новый старт использует общие изменяемые `state` и `pinging`. Результат старого запроса может попасть в новый запуск или нарушить планирование цикла.
- **Поздний красный статус:** порог 20 ошибок, особенно при большом числе сайтов, может отложить красный статус на много минут. Новый порог настраивается, по умолчанию три ошибки подряд.
- **Ложное «Доступно»:** верхний счётчик считает доступными все адреса, которые ещё не достигли порога 20 ошибок, включая ни разу не проверенные и текущие таймауты.
- **Пустая строка как таймаут:** отсутствие результата `p == null` отображается как «Таймаут», хотя запрос мог ещё не выполняться. Новая версия различает ожидание и ошибку.
- **Повреждение ввода:** изменение количества сайтов пересоздаёт все поля и теряет введённые адреса, подставляя `google.com` в первое поле.
- **Слабый CSV-импорт:** читается только первая строка, отсутствует разбор кавычек/многострочных полей и нет полноценного обратного импорта отчёта.
- **Неполный CSV-экспорт:** поля не экранируются; экспортируемый статус не отражает предупреждения таблицы.
- **Фиктивная анимация:** график всегда обновляется через `chart.update('none')`, поэтому переключение анимации не соответствует заявленному действию.
- **Зависимость от CDN:** без загрузки Chart.js не создаётся график, а ошибка инициализации может остановить часть запуска.
- **Нет долговременной конфигурации:** список сайтов, порядок и статистика не сохраняются между открытиями.
- **Нет управления отдельными адресами:** отсутствуют постоянный порядок и отдельный переключатель «Не опрашивать».
- **Нет нативной фоновой модели:** в исходнике нет Android service, системного уведомления и управления жизненным циклом Android.

## Решение

Сетевой цикл вынесен из UI в отдельный foreground service с явным действием остановки. Такой сервис показывает системное уведомление и предназначен для работы, заметной пользователю, даже когда он не взаимодействует с приложением. ([Обзор foreground services](https://developer.android.com/develop/background-work/services/fgs?hl=en))

Вместо браузерных ограничений используются нативные HTTP/TCP-проверки и системный ICMP `ping`. Конфигурация и история сохраняются локально, запросы ограничены по времени и параллельности, старый пакет при изменении настроек отменяется. Список адресов не привязан к их порядковым номерам: статистика хранится по нормализованному полному адресу.

Цветные значки не обещаются в верхней строке состояния: Android отображает эту область монохромно. Приложение использует различимую форму круга для общего статуса и цветные кружки в раскрытом уведомлении и интерфейсе. ([Рекомендации Android по уведомлениям](https://developer.android.com/design/ui/mobile/guides/home-screen/notifications))

Foreground service не является обходом Doze и не даёт гарантии непрерывности на всех телефонах. Для основной задачи мониторинга с выключенным экраном предусмотрены настройки исключения из оптимизации и отключаемый wake lock; реальные ограничения конкретной прошивки требуют проверки на телефоне. ([Doze и App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby))
