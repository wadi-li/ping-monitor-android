# Проверка выпуска 1.0.0

Проверка выполнена 4 ноября 2026 года. Итоговый [GitHub Actions run](https://github.com/wadi-li/ping-monitor-android/actions/runs/41856831278) завершился успешно для исходников `83ef3fa3d966d618e123c4e384afdee1d951952c`; последующие изменения перед тегом затрагивают только документацию и снимки.

## Фактически выполнено

- **JVM:** 66 успешных проверок `tools/test-core.sh`. Проверены URL/IDN/IPv6, протоколы и порты, сохранение HTTP-пути и query, дедупликация, лимит адресов, CSV/BOM/кавычки/обратный импорт отчёта, статусы, статистика, ограничение истории и неблокирующая отмена.
- **Сетевые интеграции:** настоящие HTTP/TCP-запросы к временным локальным серверам: ответы 204, 404, 500, 403, 429, HEAD → GET, перенаправление, цикл перенаправлений, таймаут, открытый и закрытый TCP-порт, отмена активного запроса.
- **Android:** 35 instrumentation-проверок на Android 15 / API 35, x86_64, профиль Pixel 2. Проверены перестановка и сохранение порядка, отключение/возобновление адреса, отсутствие запросов к изначально отключённым адресам, зелёный/красный статусы, работа после сворачивания Activity, остановка, восстановление списка и статистики, переключение тем.
- **Уведомление:** через `NotificationManager.getActiveNotifications()` подтверждены реальная регистрация уведомления, флаг foreground service, нужный красный агрегированный small icon, наличие цветного large icon и expanded RemoteViews. Применение expanded RemoteViews к нативному View прошло успешно.
- **Сборки:** `assembleDebug`, `assembleRelease`, `assembleDebugAndroidTest` выполнены; отдельно успешно проверена сборка с чистым пользовательским каталогом без заранее подготовленного debug-ключа.
- **Статический анализ:** `lintDebug`: 0 ошибок, 5 предупреждений `SetTextI18n`/`HardcodedText`. Они касаются локализации строк; текущий интерфейс русский.
- **Подпись:** `apksigner verify` успешно проверил итоговый release APK. GitHub CI дополнительно сверяет постоянный SHA-256 сертификата; ключ не находится в репозитории.

## Границы визуальной проверки

Светлая и тёмная темы осмотрены по чистым снимкам предыдущего успешного прогона с тем же production-кодом. В последнем прогоне над приложением появился системный диалог `Pixel Launcher isn't responding`; это диалог лаунчера эмулятора, а не отчёт об ANR Пинг-монитора. Такие перекрытые снимки не используются как доказательство качества интерфейса.

Снимок после команды раскрытия шторки не показал реальную шторку и не считается её визуальной проверкой. Регистрация и содержимое уведомления проверены программно; реальное отображение expanded-уведомления в SystemUI/OEM на телефоне пользователя остаётся отдельным приёмочным тестом.

## Не проверено на телефоне пользователя

- Поведение конкретной прошивки с выключенным экраном, в длительном Doze и энергосбережении.
- Политики фоновых приложений Samsung, Xiaomi/HyperOS, Huawei и других производителей.
- Собственные адреса пользователя, VPN, корпоративный DNS, captive portal и реальные HTTPS-сертификаты этих узлов.
- Работа системного ICMP `ping` в конкретной прошивке и фильтрация echo реальными узлами.
- Автоматическое восстановление после убийства процесса системой. После force-stop и перезагрузки требуется ручной запуск.
- Непрерывный многочасовой/многодневный прогон, измерение трафика и расхода батареи.
- Все версии Android 8+ и все размеры экранов; совместимость по minSdk не заменяет такой проверки.
- Пользовательский цикл импорта/экспорта через файловые провайдеры каждой прошивки; CSV-логика покрыта JVM-тестами, SAF-диалоги требуют полевой проверки.

Фоновый сервис сам по себе не снимает ограничения Doze на сеть и wake lock. Для постоянного мониторинга с выключенным экраном нужно настроить исключение из оптимизации и, при необходимости, разрешить фоновую работу в настройках производителя. ([Документация Android](https://developer.android.com/training/monitoring-device-state/doze-standby))
